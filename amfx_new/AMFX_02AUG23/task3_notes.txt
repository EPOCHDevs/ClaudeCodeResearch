==========================================================
Status: IN_PROGRESS — Definition written, not yet run.

Run config override: start=2018-01-01, end=2023-08-31

Data Source
-----------
- FRED series: WCESTUS1 (same as Task 2)
- Transform: week-over-week change = (current_stocks - prior_stocks) / 1000 → millions of barrels
- Mode: use_alfred=False
- ~280 weekly data points over 5.5 years (2018-01 to 2023-08)

Chart Approach
--------------
- Transform: xy_lines
- X-axis: timestamp (index()) — continuous time axis
- Y-axis: weekly inventory change in millions of barrels
- Single blue line series
- Reference line at zero
- Data is sparse (non-NaN only on weekly release dates); xy_lines should handle NaN gaps
  by connecting only non-NaN points

Key Features to Capture
-----------------------
1. COVID-era builds (early 2020): massive positive spikes around +15M barrels
2. Post-COVID draws (2020-2021): sustained negative territory
3. 2022 oscillation around zero
4. July 2023 record draw at the tail end — the visual punch line

Known Differences from Original
---------------------------------
1. EIA vs API data source (same caveat as Task 2)
2. Sparse daily grid (weekly release days only have values) means the line will have
   straight-line connections between weekly points. Original shows a smooth weekly line.
3. Y-axis range should be similar (-20 to +15 million barrels)

Potential Issue
---------------
- xy_lines with ~97% NaN data (daily grid, weekly releases): the line should render
  correctly since xy_lines passes x,y pairs and NaN y-values are skipped.
  If it doesn't render well, alternative: forward-fill crude_change_m so the line
  shows a step pattern (each week's change held until next release).
