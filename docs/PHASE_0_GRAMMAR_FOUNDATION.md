# Phase 0 — Grammar Foundation

**Status:** Not started
**Goal:** Parser routing infrastructure + grammar documentation structure + builtin/macro dispatch architecture ready before any new constructs exist.
**Touches:** `grammar_generator.cpp`, `constructor_parser.cpp`, new files: `builtin_lowering.h`, `macro_expander.h`, `builtin_registry.h`, `lowering_strategies/*.h`

---

## What the grammar doc is

The EBNF file generated by `grammar_generator.cpp` is the **documentation surface and contract for Layers 1 and 2**. It is what agents and users read. The compiler validates against it.

Layer 3 registered transforms are documented in the EpochAI search index — that is a separate system and is not touched here.

```
grammar doc (epochscript.ebnf)
  → Layer 1 builtins: documented here (EBNF comment blocks)
  → Layer 2 macros:   documented here (EBNF production rules + expansion comments)
  → Layer 3 transforms: NOT here — use find_by_id() in EpochAI

compiler
  → validates Layer 1/2 call shapes against grammar contract
  → macro expansion produces existing Layer 3 impl nodes
```

## 0a — `COMPILER_MACROS` array in grammar_generator.cpp

### What it does

`constructor_parser.cpp` currently routes on two conditions:
1. Name in `BUILTIN_FUNCTIONS` → single-stage parse path
2. Anything else → two-stage parse (`fn(opts)(inputs)`)

Layer 2 macros need single-stage routing. A `COMPILER_MACROS` array parallel to `BUILTIN_FUNCTIONS` is the extension point.

### Change in `grammar_generator.cpp`

Add after `BUILTIN_FUNCTIONS` constant (line ~114):

```cpp
// Compiler macros — single-stage, inputs-first fn(inputs..., options...).
// Parser routes these to the single-stage path, same as BUILTIN_FUNCTIONS.
// Expansion logic in constructor_parser.cpp handles variadic emit.
// Populated as phases 1-3 implement each macro.
const std::vector<std::string> COMPILER_MACROS = {
    // "resample",           // Phase 1
    // "marker",             // Phase 3
    // "candlestick_pattern",// Phase 3
    // "macro_data",         // Phase 3
    // "pair_stat",          // Phase 3
    // "volatility",         // Phase 3
    // "select",             // Phase 3
};
```

### Change in `constructor_parser.cpp`

Extend the single-stage detection to include `COMPILER_MACROS`:

```cpp
// Before:
bool is_single_stage = IsMember(BUILTIN_FUNCTIONS, name);

// After:
bool is_builtin = IsMember(BUILTIN_FUNCTIONS, name);
bool is_macro   = IsMember(COMPILER_MACROS, name);
bool is_single_stage = is_builtin || is_macro;

// Expansion path diverges:
if (is_builtin) {
    // lower to single impl node (existing builtin lowering logic)
} else if (is_macro) {
    // route to macro expander — emits N impl nodes via variadic expansion
}
```

## 0c — Validation: two-stage form of a macro name is a COMPILE ERROR

Once a name is in `COMPILER_MACROS`, any attempt to use it in two-stage form is rejected:

```
resample(target_timeframe="1D")(src.c)  →  COMPILE ERROR:
  "resample is a compiler macro — use single-stage form: resample(src.c, target_timeframe=\"1D\")"
```

The error message includes the corrected single-stage form.

### What it does

Registers commonly-used visualization enums in the grammar's EBNF enum reference section so agents can discover colors, dash styles, and formatting options without metadata lookups. Reporter transforms stay Layer 3 — this only surfaces the shared enum vocabulary.

### Why not promote Reporters to grammar?

Reporter transforms (26 total) have:
- 12 custom schema types (ReferenceLineSchema, PlotBandSchema, LineSeriesSchema, etc.) — nested JSON objects, not expressible as simple kwargs

## 0e — Builtin Lowering & Macro Expansion Architecture

### The problem this solves

Phases 1–5 add ~120 builtins and ~42 macros. Without dispatch architecture, all lowering logic lands as an `if/else` chain in `ParseBuiltinFunctionCall()` — a 3000+ line god function that's untestable in isolation and violates single responsibility.

The existing codebase solves this pattern for other concerns:
- `OptionTypeFactory` + `OptionTypeRegistry` — pluggable option parsing
- `ISpecialNodeValidator` + `SpecialNodeValidatorRegistry` — pluggable validation
- `GenericFunctionResolver` — pluggable type-based resolution

This section establishes the equivalent for builtin lowering and macro expansion.

### Strategy interfaces

```
epoch-script/include/epoch_script/transforms/compiler/
├── builtin_lowering.h          ← IBuiltinLowering interface
├── macro_expander.h            ← IMacroExpander interface
├── builtin_registry.h          ← BuiltinRegistry (owns both maps)
└── lowering_strategies/        ← reusable strategy implementations
    ├── same_name_period.h      ← fn(src, N) → fn(period=N)(src)
    ├── same_name_no_param.h    ← fn(inputs...) → fn()(inputs...)
    ├── alias_lowering.h        ← fn(src) → other_fn()(src)
    ├── arithmetic_lowering.h   ← fn(args) → arithmetic expression nodes
    ├── ma_alias_lowering.h     ← fn(src, N) → ma(type=X, period=N)(src)
    ├── multi_period_lowering.h ← fn(src, short, long) → fn(short=X, long=Y)(src)
    ├── period_boundary.h       ← fn(offset) → is_period_boundary(period=X, boundary=Y, ...)
    ├── enum_gated_lowering.h   ← fn(EnumValue) → impl(enum_option=Value)
    ├── datasource_lowering.h   ← fn(kwargs...) → datasource impl node
    ├── single_impl_multi_output.h  ← macro: 1 impl node → N output slots
    └── variadic_input_expander.h   ← macro: N inputs → N impl nodes
```

### `IBuiltinLowering` — single impl node output

```cpp
// builtin_lowering.h
#pragma once

struct LoweringResult {
    std::string impl_node_id;           // e.g. "rsi"
    OptionMap options;                    // e.g. {{"period", 14}}
    std::vector<ValueHandle> inputs;     // ordered feed inputs
    // Metadata for type checking:
    std::optional<DataType> output_type; // override if non-Decimal (Timestamp, Int, Boolean)
};

class IBuiltinLowering {
public:
    virtual ~IBuiltinLowering() = default;

    /// Lower a single-stage builtin call to an impl node specification.
    /// @param name     Builtin name as written in source (e.g. "rsi")
    /// @param args     Positional arguments (series expressions, literals)
    /// @param kwargs   Named keyword arguments
    /// @param ctx      Compilation context for error reporting + variable resolution
    /// @throws CompileError on invalid arguments
    virtual LoweringResult Lower(
        const std::string& name,
        const std::vector<ValueHandle>& args,
        const KwargMap& kwargs,
        CompilationContext& ctx
    ) const = 0;

    /// Argument count validation (called before Lower for early error).
    virtual ArgSpec GetArgSpec() const = 0;
};

struct ArgSpec {
    int min_positional;       // e.g. 1 for rsi(src, N) where N has default
    int max_positional;       // e.g. 2 for rsi(src, N); -1 for variadic
    std::vector<std::string> kwarg_names;  // valid keyword arg names
};
```

### `IMacroExpander` — multi-node output

```cpp
// macro_expander.h
#pragma once

struct ExpansionResult {
    struct NodeSpec {
        std::string impl_node_id;
        OptionMap options;
        std::vector<ValueHandle> inputs;
        std::string output_handle;       // slot name for tuple unpacking
        std::optional<DataType> output_type;
    };
    std::vector<NodeSpec> nodes;         // N nodes emitted
};

class IMacroExpander {
public:
    virtual ~IMacroExpander() = default;

    /// Expand a macro call to N impl node specifications.
    /// @throws CompileError on invalid arguments or expansion failure
    virtual ExpansionResult Expand(
        const std::string& name,
        const std::vector<ValueHandle>& args,
        const KwargMap& kwargs,
        CompilationContext& ctx
    ) const = 0;

    virtual ArgSpec GetArgSpec() const = 0;

    /// Number of output slots (for tuple unpacking validation).
    /// -1 if output count depends on arguments (e.g. candlestick_pattern).
    virtual int OutputCount() const = 0;
};
```

### `BuiltinRegistry` — dispatch hub

```cpp
// builtin_registry.h
#pragma once

class BuiltinRegistry {
public:
    static BuiltinRegistry& Instance();

    // Registration (called during InitializeTransforms)
    void RegisterBuiltin(const std::string& name, std::unique_ptr<IBuiltinLowering> strategy);
    void RegisterMacro(const std::string& name, std::unique_ptr<IMacroExpander> strategy);

    // Dispatch (called from constructor_parser.cpp)
    bool IsBuiltin(const std::string& name) const;
    bool IsMacro(const std::string& name) const;
    const IBuiltinLowering& GetBuiltin(const std::string& name) const;
    const IMacroExpander& GetMacro(const std::string& name) const;

    // For grammar_generator.cpp — replaces hardcoded arrays
    std::vector<std::string> GetBuiltinNames() const;
    std::vector<std::string> GetMacroNames() const;

private:
    std::unordered_map<std::string, std::unique_ptr<IBuiltinLowering>> builtins_;
    std::unordered_map<std::string, std::unique_ptr<IMacroExpander>> macros_;
    mutable std::mutex mutex_;
};
```

### constructor_parser.cpp — becomes thin dispatch

The current `ParseBuiltinFunctionCall()` becomes a ~30-line dispatcher. No if/else chain:

```cpp
ValueHandle ConstructorParser::ParseBuiltinFunctionCall(
    const std::string& name, const CallExpr& call
) {
    auto args   = CompilePositionalArgs(call);
    auto kwargs = CompileKwargs(call);
    auto& registry = BuiltinRegistry::Instance();

    if (registry.IsBuiltin(name)) {
        auto& strategy = registry.GetBuiltin(name);
        ValidateArgCount(name, args, strategy.GetArgSpec());
        auto result = strategy.Lower(name, args, kwargs, ctx_);
        return node_factory_.CreateFromLowering(result);
    }

    if (registry.IsMacro(name)) {
        auto& expander = registry.GetMacro(name);
        ValidateArgCount(name, args, expander.GetArgSpec());
        auto result = expander.Expand(name, args, kwargs, ctx_);
        return node_factory_.CreateFromExpansion(result);
    }

    // Existing math builtins (abs, sin, cos, etc.) — unchanged
    return HandleMathBuiltin(name, args);
}
```

### Reusable lowering strategies — covers ~90% of all builtins

Each strategy is a concrete class that implements `IBuiltinLowering`. Most builtins are registered declaratively with no custom code.

#### 1. `SameNamePeriodLowering` — ~50 builtins

`fn(src, N)` → `fn(period=N)(src)`. Covers: rsi, trix, cmo, fosc, roc, dpo, vhf, md, decay, edecay, stderr, percentrank, etc.

```cpp
class SameNamePeriodLowering : public IBuiltinLowering {
public:
    SameNamePeriodLowering(
        std::string option_name = "period",       // "period", "window", "length"
        int default_period = -1,                   // -1 = required
        std::optional<DataType> output_type = {}   // override for non-Decimal returns
    );

    LoweringResult Lower(const std::string& name, ...) const override {
        // args[0] = src, args[1] = N (or default)
        // → {impl_node_id=name, options={{option_name, N}}, inputs={src}}
    }

    ArgSpec GetArgSpec() const override {
        return {1, 2, {}};  // 1 required (src), 1 optional (period)
    }
};

// Registration (Phase 5):
registry.RegisterBuiltin("rsi",         make<SameNamePeriodLowering>());
registry.RegisterBuiltin("trix",        make<SameNamePeriodLowering>());
registry.RegisterBuiltin("highestbars", make<SameNamePeriodLowering>("period", -1, DataType::Int));
registry.RegisterBuiltin("streak_length", make<SameNamePeriodLowering>("period", 1, DataType::Int));
```

**Unit test for this ONE class covers 50 builtins:**

```cpp
TEST_CASE("SameNamePeriodLowering") {
    SameNamePeriodLowering strategy("period", -1);

    SECTION("basic lowering") {
        auto result = strategy.Lower("rsi", {src, lit(14)}, {}, ctx);
        REQUIRE(result.impl_node_id == "rsi");
        REQUIRE(result.options.at("period") == 14);
        REQUIRE(result.inputs == vector{src});
    }

    SECTION("missing required period") {
        REQUIRE_THROWS_WITH(
            strategy.Lower("rsi", {src}, {}, ctx),
            ContainsSubstring("period required")
        );
    }

    SECTION("default period") {
        SameNamePeriodLowering with_default("period", 14);
        auto result = with_default.Lower("rsi", {src}, {}, ctx);
        REQUIRE(result.options.at("period") == 14);
    }

    SECTION("output type override") {
        SameNamePeriodLowering typed("period", -1, DataType::Timestamp);
        auto result = typed.Lower("arg_max", {src}, {}, ctx);
        REQUIRE(result.output_type == DataType::Timestamp);
    }
}
```

### Macro expander strategies

#### 1. `SingleImplMultiOutputExpander` — ~30 macros

Routes to one impl node, unpacks N named output slots.

```cpp
class SingleImplMultiOutputExpander : public IMacroExpander {
```

### Testing architecture

**Unit test each strategy class independently** — no need for full compilation pipeline:

```
epoch-script/test/unit/compiler/
├── lowering_strategies/
│   ├── same_name_period_test.cpp        ← tests SameNamePeriodLowering with mock ctx
│   ├── same_name_no_param_test.cpp
│   ├── alias_lowering_test.cpp
│   ├── arithmetic_lowering_test.cpp
│   ├── ma_alias_lowering_test.cpp
│   ├── multi_period_lowering_test.cpp
│   ├── period_boundary_test.cpp
│   ├── enum_gated_test.cpp
│   ├── datasource_lowering_test.cpp
│   ├── agg_lowering_test.cpp           ← custom
│   └── resample_expander_test.cpp      ← custom
├── builtin_registry_test.cpp            ← dispatch + registration tests
└── macro_expansion_test.cpp             ← tuple unpacking, output count validation
```

**Key principle: one test class covers N builtins.** Testing `SameNamePeriodLowering` once with parameterized inputs gives confidence for all 45 builtins that use it. Integration tests in later phases verify the registration is correct (right name → right strategy → right impl node).

**Integration test pattern (per phase):**

```cpp
TEST_CASE("Phase 5a: MA aliases integration") {
    for (auto& [name, type] : {
        {"ema", "ema"}, {"sma", "sma"}, {"hma", "hma"}, ...
    }) {
        SECTION(name) {
            // Compile: fn(close, 14) → verify produces identical output to ma(type=X, period=14)(close)
            auto builtin_result = CompileAndRun(name + "(close, 14)");
            auto legacy_result  = CompileAndRun("ma(type=" + type + ", period=14)(close)");
            REQUIRE(builtin_result == legacy_result);
        }
    }
}
```
